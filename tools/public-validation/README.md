# 优化器实验效率验证

这里不验证“算法是否高级”，只回答一个产品问题：

> 已有少量实验但尚未达标时，Ingot 能否用更少的追加实验找到达标工艺？

公开数据只能验证方法在固定实验池中的选点效率，不能代替真实工厂试点。所有方法共享同一初始历史，只能看到已经执行实验的结果；候选结果在被选中前保持隐藏。

## 要达到什么目的

先用白话说明三个比较对象：

- **稳定趋势方法**：根据已经看到的方向继续尝试，例如温度升高时结果持续改善；专业名称是线性响应面。
- **拐点与组合方法**：允许“升到某个区间最好，再升反而变差”，也允许两个参数搭配后才有效；专业名称是二次响应面。
- **更灵活的小样本方法**：在简单规律解释不够时，根据预测结果和不确定性选择下一项实验；这里使用高斯过程。

当前验收分成两项，互不冒充：

1. **核心选点能力**：相对随机搜索和 maximin 明显减少追加实验；遇到适合稳定趋势或拐点/参数组合的问题时不明显退化；简单规律不够时，允许高斯过程带来额外收益。
2. **机理特征贡献**：只在预先声明的物理特征确实改善可见数据上的预测，并在配对消融中减少实验时通过。未通过时关闭这些特征，不影响核心选点能力使用原始控制量继续工作。

核心能力不是“永远用贝叶斯优化”，而是**从当前证据支持的方法里选一个**。工程师只提供目标、可调参数、成本和安全边界，不需要选择算法名称。

## 怎么判定

每个回放 episode 从相同、随机且不重复的初始实验开始，比较以下方法：

- 当时冻结的 Ingot 方法选择策略；
- 固定种子随机搜索；
- 序贯 maximin 空间填充；
- 稳定趋势方法（正则化线性响应面）；
- 拐点与参数组合方法（正则化二次响应面）；
- 同一 Ingot 策略关闭机理特征后的配对消融。

主要指标是“达到目标所需的截断追加实验数”，同时报告预算内达标率、95% 置信区间和每个数据集的结果。随机与 maximin 用优效性检验；线性与二次响应面用非劣效性护栏，因为它们本身就是有效的实验缩减方法。合计数字不能掩盖某个数据集的明显退化。

验证只有三个易懂的状态：

| 状态 | 用途 | 能说明什么 |
|---|---|---|
| 开发回归 | 用已经看过的数据改进和防止退化 | 代码按预期工作，不能作为新效果证据 |
| 未见数据验收 | 先冻结方法、数据选择和规则，再查看结果 | 当前策略能否通过公开数据验收 |
| 真实试点 | 使用客户自己的历史和前瞻实验 | 能否为该工艺减少实际实验 |

文件名中的旧编号只是过去内部实验批次，不是产品版本，也不是用户需要理解的成熟度等级。它们作为审计记录保留；当前结论只看本页列出的验收状态。

| 核心选点能力 | 历史冻结结果有成功分项，但没有一轮同时通过全部预注册基线与数据集护栏 |

## 保留的冻结证据

| 冻结评估 | 主要观察 | 判定 |
|---|---|---|
| 450 次 Alkox、P3HT 与 HPLC 配对回放 | 相对随机减少 `49.24%`，相对 maximin 减少 `62.96%`；但 Alkox 和 P3HT 明显落后于线性响应面，与二次响应面轨迹相同 | 核心验收未通过；完整结果见 [acceptance-results.json](acceptance-results.json) |
| 400 次未见反应过程配对回放 | 总体成功率 `85.5%`，合计优于所测线性和二次响应面；未通过相对随机和 maximin 的预注册门槛 | 核心选点能力未证明；完整结果见 [unseen-results.json](unseen-results.json) |
| 400 次 OER 组成板配对回放 | 合计结果明显优于多个基线，但没有通过所有组成板上的二次响应面护栏 | 全部基线优势未证明；完整结果见 [latest-results-v7.json](latest-results-v7.json) |
| 预注册特征消融 | 过程交互与组成描述符均未显示稳定增量贡献 | 机理特征贡献未证明 |

这些结果属于不同冻结候选和数据选择，不能横向拼成一个“总体胜率”，也不能把某轮成功分项移植到当前策略。算法、数据、目标、预算或门槛变化后，旧结果只用于开发回归和失败审计。

## 怎么运行

运行当前开发回归：

```bash
./scripts/benchmark-optimizer-development.sh
```

检查保留的冻结验收数据与协议完整性，并确认当前算法不再匹配旧指纹：

```bash
./scripts/verify-optimizer-acceptance.sh
```

`./scripts/benchmark-optimizer-acceptance.sh` 只复现已冻结的正式结果；当前算法已变化，因此会按设计拒绝运行。后继算法在已披露数据上的开发回归使用 `./scripts/benchmark-optimizer-development.sh`。

结果必须完整保留所有基线、数据集分项、置信区间和失败项。算法、数据、目标、预算或门槛发生变化后，旧结果只能作为开发回归，不能重新包装成当前策略的未见数据验收。
