本目录只保留当前开发入口。它读取已经查看过结果的数据，用于定位失败和防止代码退化，不构成新的效果证据。

运行：

```bash
./scripts/benchmark-optimizer-development.sh
```

保留的冻结验收记录显示：上一策略稳定胜过随机和 maximin，并与二次响应面相同；但它在 Alkox 和 P3HT 上分别比线性响应面多用 32.08% 和 68.36% 的追加实验。当前后继策略默认使用线性面，只有归一化目标排序误差在连续三个扩展历史中的改善都超过一个标准误才升级二次面；证据不明确时保留线性面。这里的重跑只检查这套实现是否修复已知失败，不产生新的效果证据。

按原协议规模运行 450 个开发 episode，后继策略相对随机搜索减少 50.57%、相对 maximin 减少 63.93%、相对线性响应面减少 14.32%，这三项通过原门槛；相对二次响应面总体减少 2.61%，但 HPLC 分项为 −26.47%，因此总体仍判 `not-demonstrated`。这组结果已经参与方法开发，只能作为失败定位和回归信息。

任何后继策略都可以使用当前验收数据做开发回归，但不得把重跑结果称为独立验收。新的效果判定必须先提交后继算法，再选择另一批从未查看结果的数据并冻结规则。
