# 真实场景演示：数据体检 + 证据定级

**这是当前环境下能立即运行的"真实场景"**——因为构建环境无 .NET SDK（网络受限，无法编译平台），本演示用**产品的实际迁移 schema 与实际定级探针 SQL**，在**真实 PostgreSQL 16** 上处理现场形态的光学模压数据，端到端跑通核心链路：

```
历史 CSV（现场导出）→ 生产事件 → 数据体检 → 证据定级（诚实降级）→ 可发管理层的报告
```

它证明的是核心逻辑在真实数据上成立；也是 .NET 版本（`CaseLevelEvaluator` / `ingot-import`）的集成参照——两者跑同一套 SQL。

## 运行

需本机 `psql` 与一个 PostgreSQL（普通 PG 即可；生产用 timescaledb 镜像）：

```bash
bash scripts/demo/run-health-demo.sh
```

## 文件

- `sample-optical-molding.csv` —— 现场形态数据：M-01 设备、LENS-A 产品、MOLD-02/MOLD-09 两副模具、55 个周期、381 条事件。**故意注入现场真实缺陷**：3 个 MOLD-02 周期缺完工事件（机台跳停未闭合）、MOLD-09 的 `press_force` 用 `N` 而 MOLD-02 用 `kN`（量纲混乱）。
- `health-demo.sql` —— 加载 → 映射（模拟 `ingot-import`）→ 运行产品定级探针 → 打印报告。
- `run-health-demo.sh` —— 便携编排（组装真实迁移、建库、跑报告）。
- `health-report.html` —— 渲染好的体检报告（发现场/管理层）。

## 本次运行结果（真实数据）

| 门槛 | 实测 | 阈值 | 结果 |
|---|---|---|---|
| 周期配对率 | 92.5% (37/40) | ≥95% | ❌ |
| 生产信息缺失率 | 0.0% | <5% | ✅ |
| 时钟异常 | 0 | =0 | ✅ |
| 单位冲突 | 1（press_force：N vs kN） | =0 | ❌ |
| 阶段覆盖 (L1) | 93% | ≥90% | ✅ |
| 同类可比 (L2) | 37 | ≥30 | ✅ |

**结论：L0-pending**。L1/L2 虽满足，但 L0 未清零，档案诚实停在 L0-pending——先补齐配对与量纲，再谈过程分析。这正是"你以为你有数据，其实有周期没闭合、量纲还不统一"的现场价值。

## 换成你们厂的真实数据

把 `sample-optical-molding.csv` 换成你们采集库导出的历史 CSV（列名按 `health-demo.sql` 里的映射调整，或直接改映射），即可对**真实生产数据**出同样的体检+定级报告。这就是给老板看的第一份东西。
