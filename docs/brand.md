# 品牌规范

> 文档状态：**v1 规范基线**。本文件是产品定位、核心价值和公开措辞的唯一事实源。除非产品方向真实改变，否则不重新定义核心价值。

## 核心价值

> **把每次真实运行变成可比较、可验证的工程证据，帮助工艺工程师减少无效实验，更快找到达到目标的工艺条件。**

“减少无效实验”是产品要交付的结果，不是某一种算法的同义词。数据采集、工艺追因、实验设计、线性或二次响应面、贝叶斯优化、机理融合和模型交互都是服务于这个结果的手段。

## 产品定位

- **产品类别**：开源工艺追因与优化系统 / Open-source Process Diagnosis & Optimization
- **主要用户**：负责新产品、新材料和新工艺开发的工艺、质量、设备和研发工程师
- **工作对象**：一次真实运行的生产条件、过程轨迹、质量结果、工程判断和后续实验
- **产品职责**：整理可信事实、比较运行差异、形成可验证候选、辅助选择下一步实验并保留结论边界
- **工程师职责**：确定问题、审核数据与约束、判断建议是否可执行、批准实验并解释现场条件
- **系统边界**：Ingot 不代替工程师，不绕过安全约束、审批职责或设备控制系统

Ingot 不是为了“多采一些点位”，也不是为了展示某一种算法。它把采集到的数据变成工程师可以使用的证据，再根据问题选择稳健统计、对照比较、实验设计、因果验证、机器学习、贝叶斯优化、机理模型或语言模型。

“工艺研发”是产品信息架构中的业务入口，覆盖候选验证、实验设计、安全优化和研发成果；“优化”是产品类别中对选择下一步实验能力的概括，不是独立一级菜单，也不表示系统自动写入设备。

## 公开承诺

公开内容可以承诺系统提供以下能力：

- 关联实际生产条件、过程轨迹和检验结果；
- 显示数据缺失、来源、版本和不确定性；
- 帮助工程师比较运行、缩小候选原因范围；
- 把候选原因转成可证伪实验；
- 在声明的变量和安全边界内推荐下一步实验；
- 将经过验证的结论保存为有适用范围的工艺知识。

公开内容不得在没有真实项目证据时声称：

- 系统已经自动发现确定根因；
- 系统已经减少某个百分比的实验或研发时间；
- 模型推荐等同于现场保证；
- 一个成功参数点已经证明完整工艺操作域；
- 一个场景的结果可以无条件迁移到其他场景。

观察数据只能形成候选原因、稳定关联或证据不足的判断。因果结论必须经过工程判断和适当的对照、重复、区组或干预实验。

## 规范用语

| 用途 | 中文 | English |
|---|---|---|
| 产品类别 | 开源工艺追因与优化系统 | Open-source Process Diagnosis & Optimization |
| 核心价值 | 少做无效实验，更快找到达标工艺 | Avoid unproductive experiments and reach target process conditions faster |
| 简短标语 | 看清这次运行，做对下一项实验。 | Understand this run. Choose the right next experiment. |
| 数据单位 | 运行 / 过程执行 | run / process execution |
| 观察结论 | 候选原因、稳定关联、混杂关联、证据不足 | candidate cause, stable association, confounded association, insufficient evidence |
| 实验结论 | 支持、否决、不确定、已验证原因 | supported, rejected, inconclusive, validated cause |
| 证据等级 | 证据不足、探索性证据、证据稳定、证据充分 | insufficient, exploratory, stable, sufficient |
| 优化结果 | 下一步实验建议、候选设置、已验证工艺操作域 | next-experiment recommendation, candidate setting, validated operating region |

“过程执行”是平台中的标准业务对象；面向工程师的简短文案可使用“运行”，但代码、接口和跨场景文档不使用特定设备的周期名称代替它。

证据等级回答“当前支撑有多强”，观察结论回答“观察到了什么关系”，实验结论回答“干预是否支持假设”，三者不得互换。“仅稳健筛选”（`screening`）和“证据有限”（`limited`）是第一、第二级的降级说明，不新增结论类别。

“根因”只在已经说明验证证据时使用。“AI 工艺研发”可以描述交互方式，但不能替代产品类别。具体算法名只出现在技术说明中，不作为产品价值本身。

不得把长期自动化愿景、尚未形成外部采用的规范候选或未来受控行动能力表述为当前产品类别、行业标准或已实现收益。

简短标语是核心价值的传播缩写，不是另一套产品定义。

## 文档语体

公开文档采用正式、直接、可核验的工程语体：

- 面向工程师的首页、入门、FAQ 和界面先说“系统建议做什么、为什么、风险是什么”，不要求用户理解模型名称；例如写“沿当前稳定趋势继续试”，不先写“使用线性响应面”。
- 算法、架构、验证协议和开发文档保留专业术语、公式条件和统计门槛；术语首次出现时补一句白话解释，不用模糊口号替代技术精度。
- 同一事实允许分层表达：用户文档解释业务含义，技术文档给出模型名称和判定规则；两层的结论强度必须一致。
- 先说明对象、能力和结果，再说明实现方法；不使用人格化的“思考”“理解”“大脑”代替具体计算或工作流。
- 明确区分已实现能力、测试结果、开发期证据、外部验证和路线图，不把计划写成现状。
- `AI`、`LLM`、高斯过程和贝叶斯优化只在说明具体技术职责时出现，不作为效果形容词。
- 定量结果同时给出数据范围、比较基线、指标、置信区间和适用边界；没有这些要素时不写成收益结论。
- 操作说明使用明确命令和预期结果；产品说明避免口号堆叠、反问、自我评价和对读者的推销式称呼。
- 中英文文档保持相同的信息层级和结论强度。翻译可以调整句式，但不得增加能力、收益或保证。

允许使用“帮助”“建议”和“候选”，前提是同时明确工程师审核、安全边界和证据等级。界面名称、接口字段和命令保持原样，不为追求文风而改写技术标识。

## 标识释义

Ingot 的标识由三块锭的截面堆叠而成：

- 两块钢色底锭代表持续积累的运行数据、实验记录和工程知识；
- 顶部金锭代表从证据中形成、仍可追溯和复核的当前判断；
- 三块锭之间的等距缝隙表示事实、分析和结论保留独立来源。

## 使用规则

- 最小展示尺寸为 16px，四周留白不小于单块锭高度的一半。
- 不改变三块锭的比例、位置关系与配色，不额外添加描边、阴影或倾斜。
- 字标使用 `Inter` / `Segoe UI` Bold 回退族。
- 公开视觉以设备信号、阶段轨迹、检验记录和工程决策为主体，不使用火焰、熔融材料、加热容器或神秘主义意象。
- 产品效果必须区分模拟演示、历史回放、影子建议和真实在线实验。
- README、文档站、官网 metadata 和产品介绍必须与本文件的核心价值、类别和承诺边界一致。
