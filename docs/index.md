# Ingot 文档

> **核心价值**：把每次真实配方运行变成优化证据，在安全边界和历史覆盖范围内持续推荐下一份配方。

Ingot 是开源工艺追因与优化系统。系统统一关联运行条件、过程轨迹、生产上下文和质量结果，让正常生产中的配方运行直接形成优化观察，并据此给出下一份配方建议。

文档无需按顺序阅读，可根据当前任务选择入口。

## 产品闭环

```text
工艺配置 → 现场接入 → 生产运行 → 质量管理 → 工艺追因 → 配方优化
    ↑                                                      ↓
    └────────── 已验证工艺规范、工艺操作域与知识返回生产 ──────────┘
```

1. **工艺配置**说明系统要认识哪些变量、单位、质量规则和安全边界。
2. **现场接入**把控制系统、仪器和业务数据转换成统一工艺字段。
3. **生产运行**记录实际条件、阶段、轨迹和生产上下文。
4. **质量管理**唯一关联并独立复核检验结果。
5. **工艺追因**先检查数据是否可靠，再比较运行并找出值得验证的差异。
6. **配方优化**直接汇总真实配方运行，在安全边界和历史覆盖范围内给出下一份配方建议；需要确认因果或探索覆盖范围外条件时，再选择受控验证。

这个顺序表达“先有什么，后做什么”。页面菜单可以按岗位习惯排列，但分析仍必须从可信数据开始。

## 当前成熟度

主要软件流程已经可以运行，并由自动化测试覆盖。仓库不内置特定场景的验证数据或结果；使用者负责用自己的数据判断优化效果、适用范围和生产安全。

## 阅读状态标签

- **当前操作指南**：可以照着做的步骤。
- **当前事实**：已经实现、已经验证和仍有限制的内容。
- **架构或规范基线**：产品必须长期遵守的边界。
- **分阶段实现或目标设计**：包含未来内容，不能当成当前能力。
- **滚动路线图**：建设顺序会根据验证结果调整。

同一事实不在多篇入口文档中复制数字。产品类别以[品牌规范](brand.md)为准，当前成熟度以[当前状态](status.md)为准，方法数字以公开验证记录为准。
