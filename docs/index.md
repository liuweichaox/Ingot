# Ingot 文档

Ingot 是开源工艺研发与优化系统。组织配方版本、实验记录与运行证据，支持质量分析、工艺分析（包含工艺追因）和配方优化。

从本地启动到第一份建议，再到长期运维，按你的任务选择阅读路径。文档与仓库代码一同维护。[当前状态](status.md)说明已实现的能力和仍需完成的验证。

业务阅读顺序是：现场运行 → 质量检验 → 工艺分析 → 配方优化。工艺资料和机理知识属于工艺洞察；Ingot Chat 提供跨模块的核对与调查入口。

配置与接入为这条日常路径准备工艺语义，现场适配器可将设备或现有系统的数据映射并提交给 Edge。用户界面使用“工厂/生产现场”作为数据与权限边界，系统内部用 `SiteId` 标识。下一份配方调整由工程师确认，再通过既有现场流程进入下一轮运行。

## 第一次使用

按目标选择对应入口：

| 目标 | 路径 | 完成标志 |
|---|---|---|
| 本地启动并查看工作台 | [快速开始](getting-started.md) | 使用 Docker 启动核心服务，完成迁移、健康检查和登录 |
| 了解现场接入 | [数据接入](data-connection.md) | 了解现场适配器、Edge 事件接口和验收边界 |
| 评估真实运行证据流程 | [当前状态](status.md) → [配方优化试点指南](pilot.md) | 用经授权的真实运行和复核质量结果检查准入，再完成建议与后续结果记录 |
| 参与代码或文档贡献 | [贡献指南](../CONTRIBUTING.md) | 按改动范围准备工具并完成相应检查；完整提交门禁见贡献指南 |

“当前状态”用于了解已实现能力和数据边界，可在启动前或之后阅读。系统可独立启动；生成配方建议依赖符合准入条件的真实运行和质量证据。

## 支持与反馈

使用问题请附复现步骤、版本、服务状态和脱敏错误信息，在 [Issues](https://github.com/liuweichaox/Ingot/issues) 提交。方案讨论使用 [Discussions](https://github.com/liuweichaox/Ingot/discussions)。安全漏洞通过[安全策略](../SECURITY.md)中的私密渠道报告。

提交 Issue 或 Pull Request 时，材料中排除 `.env`、凭据、真实生产数据和可识别的现场信息。文档修订同步更新对应英文页。
