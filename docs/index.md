# Ingot 文档

> **核心价值**：把每次真实运行变成可比较、可验证的工程证据，帮助工艺工程师减少无效实验，更快找到达到目标的工艺条件。

Ingot 是开源工艺追因与优化系统。它把一次真实运行的生产条件、过程轨迹和检验结果连成可追溯证据，帮助工程师判断发生了什么、哪些因素值得验证，以及下一步最值得做什么。

计算机提供证据整理、比较、分析和实验建议；工艺工程师定义问题、审核数据与约束、批准实验并作出最终判断。对外入口讲清用户结果；完整方法边界与失败记录集中在验证文档中披露。

## 产品闭环

```text
工艺配置 → 现场接入 → 生产运行 → 质量管理 → 工艺追因 → 工艺研发
    ↑                                                      ↓
    └────────── 已验证工艺规范、工艺操作域与知识返回生产 ──────────┘
```

1. **工艺配置**：定义产品、工艺变量、单位、控制参数、质量指标和安全边界。
2. **现场接入**：连接控制系统、仪器、视觉、检验或业务系统，并映射稳定业务语义。
3. **生产运行**：按真实运行记录实际条件、阶段和过程轨迹。
4. **质量管理**：录入、关联和复核同一次运行的质量与安全结果。
5. **工艺追因**：检查数据可信度，比较可比运行，形成带证据、反证和混杂边界的候选原因。
6. **工艺研发**：通过受控实验验证候选，并在安全边界内选择更有价值的下一步实验。

这些步骤是一条证据链，不是六个互不相干的产品。采集先让事实可靠；分析再让事实有用；实验最终决定候选是否成立。

## 文档状态

- **规范基线**：核心价值、产品边界、证据原则和稳定架构。变化应有明确产品证据或 ADR。
- **当前策略**：现阶段采用的分析方法、默认实验设计和信息架构，可以在不改变核心价值的情况下升级。
- **滚动状态**：路线图、当前实现、已知限制和验证结果，必须随项目事实更新。

[品牌规范](brand.md) 是公开措辞的唯一事实源；技术文档不得另行定义核心价值。

## 当前事实

代码已经覆盖采集、运行重建、可比运行对比、质量结果关联、候选原因、受控实验和序贯建议的主要业务路径，并有自动化测试。公开物理实验回放已确认相对随机搜索和 maximin 的追加查询缩减；当前工作重点是让方法自动退回适用的线性或二次响应面。精确数字、分项失败和置信区间只在[公开数据实验效率验证](https://github.com/liuweichaox/Ingot/blob/main/tools/public-validation/README.md)集中维护。

当前仓库实现快照：

- Platform 业务记录、Agent 运行快照和评测证据统一落在 PostgreSQL 恢复边界内；
- Edge 使用本地持久化 outbox 和至少一次上送，Platform 对站点、事件身份、Schema、配置版本、内容哈希和质量标记执行失败关闭校验；
- Platform 的主要业务工作流已分到 Application，PostgreSQL Store、外部客户端和证据装配器留在 Infrastructure；API 层仍有 Edge 注册/诊断、身份和运行指标等少量运维适配器直接依赖 Infrastructure，这些是待继续收口的边界，不是新业务控制器的模板；
- 机理知识的来源、声明、审核、冲突、生命周期、硬边界、软排序、冻结快照和使用追溯已经接入；模型辅助语义草稿、Bayesian prior/机理特征/残差融合及成对长期校准仍未完成；
- 仓库提供逻辑备份/恢复、监控配置、有限故障演练和生产验收工件校验；默认 Compose 仍是单实例参考拓扑，不等于高可用生产单元，也不包含 PITR、对象存储或设备受控写入。

真实生产数据、项目与设备标识、工艺参数、质量分布和派生结果属于受控工厂证据，不进入公开仓库或公开报告。公开材料提供协议、Schema、合成样例、明确许可且带校验和的公开数据基准、验收方法和结论边界；公开基准可以独立复现软件与方法行为，但内部真实验证仍不能被公开基准替代。

当前战略顺序是：先用真实历史回放证明证据装置可复现且无未来数据泄漏，再通过前瞻影子和受控在线验证证明价值；Agent 协议和开放规范不会绕过这些证据阶段。

## 可信交付原则

- 计划值与实际值分开展示，缺失状态始终可见。
- 所有运行都保留分析准入或拒绝理由。
- 观察结果标记为候选关系，受控实验决定它是否成立。
- 数值工艺建议由受约束数值服务产生，语言模型只组织证据。
- Agent 的来源、权限、审批和设备安全边界由 Platform 强制执行。
- 每项建议保留输入、来源、版本、不确定性和适用边界。
