# Ingot 文档

> **核心价值**：让工艺研发从没有数据支撑走向有数据支撑，让计算机基于真实数据帮助工艺工程师抉择，并采用适合问题的有效计算方法分析数据。

Ingot 是开源工艺追因与优化系统。它把一次真实运行的生产条件、过程轨迹和检验结果连成可追溯证据，帮助工程师理解发生了什么、哪些因素值得验证，以及下一步最值得做什么。

计算机提供证据整理、比较、分析和实验建议；工艺工程师定义问题、审核数据与约束、批准实验并作出最终判断。系统不会把观察相关性冒充确定原因，也不会把模型建议冒充现场保证。

## 产品闭环

```text
工艺定义 → 设备接入 → 生产采集 → 数据闭环 → 工艺追因 → 工艺研发
    ↑                                                        ↓
    └──────────── 已验证工艺规范、工艺操作域与知识返回生产 ────────────┘
```

1. **工艺定义**：定义设备、产品、工艺变量、单位、控制参数、质量指标和安全边界。
2. **设备接入**：连接控制系统、仪器、视觉、检验或业务系统，并映射稳定业务语义。
3. **生产采集**：按真实运行记录实际条件、阶段和过程轨迹。
4. **数据闭环**：检查时间、缺失、来源和单位，把检验结果关联到同一次运行。
5. **工艺追因**：比较可比运行，形成带证据、反证和混杂边界的候选原因。
6. **工艺研发**：通过受控实验验证候选，并在安全边界内选择更有价值的下一步实验。

这些步骤是一条证据链，不是六个互不相干的产品。采集先让事实可靠；分析再让事实有用；实验最终决定候选是否成立。

## 文档状态

- **规范基线**：核心价值、产品边界、证据原则和稳定架构。变化应有明确产品证据或 ADR。
- **当前策略**：现阶段采用的分析方法、默认实验设计和信息架构，可以在不改变核心价值的情况下升级。
- **滚动状态**：路线图、当前实现、已知限制和验证结果，必须随项目事实更新。

[品牌规范](brand.md) 是公开措辞的唯一事实源；技术文档不得另行定义核心价值。

## 当前事实

代码已经覆盖采集、过程执行、上下文、检验、研发实验、分析和优化的主要业务路径，并有自动化测试。项目已使用受控的非公开生产历史数据完成导入、运行重建、检验关联和研发观察的内部端到端验证；正式无泄漏历史回放和前瞻验证尚未完成，因此项目只陈述系统能力，不声称已经减少具体比例的实验或研发时间。

真实生产数据、项目与设备标识、工艺参数、质量分布和派生结果属于受控工厂证据，不进入公开仓库或公开报告。公开材料只提供协议、Schema、合成样例、验收方法和结论边界；内部真实验证不等同于公开独立复现。

当前战略顺序是：先用真实历史回放证明证据装置可复现且无未来数据泄漏，再通过前瞻影子和受控在线验证证明价值；Agent 协议和开放规范不会绕过这些证据阶段。

## 公开承诺

- 不用计划值掩盖实际值缺失。
- 不静默丢弃无法进入分析的运行。
- 不把相关性直接写成确定原因。
- 不让语言模型直接生成数值工艺规范。
- 不让 Agent 绕过来源、权限、审批或设备安全边界。
- 不用模拟数据声称真实工艺收益。
- 每项建议保留输入、来源、版本、不确定性和适用边界。
