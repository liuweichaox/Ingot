# 分析与优化

> 文档状态：**当前实现与方法边界**。本页描述真实运行如何形成下一配方建议。

## 唯一业务闭环

```text
真实配方运行 + 实际参数 + 过程上下文 + 有效质量结果
                         ↓
                    优化观察
                         ↓
        下一配方建议（采用已校验的候选）
                         ↓
                     工程师决定
       ├─ 采用或修改 → 关联实际运行 → 冻结质量结果
       └─ 拒绝 → 保留拒绝原因，结束本轮
```

建议是带冻结生成条件、输入哈希、预测、不确定性和理由的追加记录，由工程师决定是否采用。工程师决定、实际运行关联和结果也分别追加，不能覆盖。修改或拒绝时必须说明原因。拒绝是终态，不能关联实际运行或冻结结果。

当前产品从已发布配方版本发起下一轮校正。采用建议只记录工程师决定，不自动创建或发布新版本，也不下发设备参数。工程师从决定之后开始的同版本运行中确认实际执行，冻结时服务端核对实际参数与决定参数的一致性。未按决定执行的结果保留为追溯记录，不计入该决定的验证。该运行能否形成后续观察，仍以实际参数和观察准入规则判断。

工程师认定属于显著变更时，再用建议参数创建该版本的修订草稿，按配置发布流程审核。工作台检测到同一现场和配方版本有未完成的校正时，会禁用生成入口。生成 API 没有每个配方版本只能有一条未完成校正的约束。同一冻结条件下已采用或修改但结果未冻结的决定，会作为待定点传给优化器。

## 准入与停止

生成建议至少需要三条有效运行和两种不同的实际可调参数组合。运行必须具有可信身份、实际参数、必要上下文和质量结果。生成所需的数据条件不满足、覆盖不足或生效的硬约束无法满足时，系统停止建议并说明原因。最低样本数是生成条件之一，实际信息量还取决于可比性、参数变化和测量质量。

## 准入失败的处理

“检查数据”的有效数量是准备情况，不保证下一次请求必然生成建议。生成请求会重新解析已发布条件和运行证据，并检查完整字段、不同实际参数组合以及优化器响应。

- **执行未完成或过程数据不可用**：核对原始运行状态、过程信号与已发布过程分析，不用计划参数补实际值。
- **缺少参数回读、过程特征或检验数值**：回到对应运行补齐数据来源。检验数值必须为有限数，`INCONCLUSIVE` 不能作为确定结果。
- **上下文覆盖或因素组合重叠不足**：核对冻结的上下文策略与工艺配置，不能混入不同范围运行以凑数量。
- **仅一种实际可调参数组合或有效运行不足三条**：等待新的真实运行，不能复制同一运行作为新样本。
- **约束、覆盖或优化器快照不一致**：保留错误与相关运行标识，核对配置和服务日志。不要扩大量程绕过包络。

准备接口返回候选数、有效数、排除数、截断标志以及最多八条排除原因示例。发生截断或排除较多时，应结合运行原始记录复核，不能把示例当作完整排除清单。

## 可追溯输入与输出

输入由已发布条件、实际运行参数、质量目标值、结果约束值、过程特征及本次适用的知识和模型组成。平台按运行标识去重。输入哈希涵盖优化器请求（包括种子）、知识声明标识和模型引用。同一工厂和配方下，相同输入哈希可以返回已有建议。建议保留冻结条件、哈希、观察数量和模型版本等信息，完整观测列表不随建议记录保存。

优化服务返回候选及其预测、不确定性、约束和覆盖信息。平台检查报告的观察数量、候选数量和覆盖变量集合。审查时核对运行事实、目标与参数的单位、参数边界，以及所用知识和模型版本。实际质量以之后的真实检验为依据。

## 观察覆盖包络

配置界限表达允许的参数范围。历史运行表明参数曾如何变化。若运行集中在当前配方附近或多个参数一同变化，模型在远离该数据范围时可能外推。

优化器在应用参数约束的同时，使用两道门限制候选点的观察覆盖范围。

- **量程门**：每个变量不得超出它在历史运行中的最小值和最大值，外加一个余量。余量取观察跨度的 10% 与变量量程的 2% 中的较大者，边界仍受配置量程限制。
- **杠杆门**：候选点相对观察数据中心的马氏距离，不得超过观察点自身的最大马氏距离再放宽 10%。距离按正则化后的协方差计算，用于限制对历史参数联合变化范围的外推。

自动采样从杠杆椭球生成候选，再检查量程门和可行性。参数高度共线时，可用区域可能远小于单变量区间形成的盒子。包络内保留的候选不足时，优化服务停止并说明原因。

配方建议仅使用 `reach-specification`（逼近规格），以预测结果达到规格为目标。优化器对返回的原始候选执行量程门和杠杆门。

优化服务返回覆盖包络。平台用同一批运行独立复算量程门，在报告缺失或量程范围不一致时停止。平台按已发布步长对齐参数后，再检查参数范围、量程门和生效的机理硬约束。对齐可能改变候选点，目前平台不重新计算杠杆门或模型预测。因此原候选通过两道门，仍需单独核实对齐后的联合覆盖和预测适用性。离线历史回放只从实际发生过的运行中选点。

## 数值方法

正式下一配方建议路径通过平台准入后，使用 BoTorch 的高斯过程和贝叶斯优化。数值服务有少于三条观察时使用的顺序优化分支，但该分支不进入平台的正式建议路径。稳健统计、响应面等其他方法按各自的分析或评估场景说明。

## 机理知识与检索

- **来源与范围**。登记原文位置、使用授权、站点和内容哈希。站点决定访问授权，配方选择器决定适用范围。同一站点的同一内容只登记一次，重复上传不能改变范围。复核片段时核对单位、条件和原文引用。
- **声明与复核**。声明记录变量与单位、版本、适用条件、证据等级、预期影响和可证伪条件，关联支持或反驳证据。来源和片段复核与声明审查分别进行。发现冲突时记录两侧版本和理由，保留解决者及结论。检索匹配只能帮助找到材料，机理结论还需单独核实。
- **建议中的使用**。适用的机理知识可提供硬约束及禁止组合，适用的机理模型可提供声明式特征。建议保留知识和模型的摘要及版本引用。未生效、存在未解决冲突或范围不匹配的声明会被排除。生效硬约束无可行范围时停止生成。平台设有软约束排序，但正式路径只请求一个候选（`top_k = 1`），当前排序不会改变选中项。
- **Ingot Chat 检索**。只检索经授权站点内已复核的来源与人工复核片段。有明确配方时加上该配方限定的资料，配方不明确时只用站点通用资料。片段级引用保留来源、页码或工作表和哈希。可选语义索引可重建，默认关闭，嵌入不可用时回落到关键词检索。权限和复核边界继续生效，启用方式见[部署运维](deployment.md)。

## 离线评估边界

离线算法评估可以使用冻结历史数据，按时间隔离未来结果，比较确定性、约束遵守和适用基线。它用于开发和方法审查，不是用户需要创建、审批或执行的业务流程，也不能证明现场收益。

## 结果与知识

对采用或修改的决定，当关联运行、参数回读、过程特征及所需检验结果齐备后，系统从源数据一次性冻结结果。决定和冻结结果为后续观察与知识更新提供追溯依据。被拒绝的建议仅留决定记录及原因。
