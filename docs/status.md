# 当前状态

> 文档状态：**滚动事实页**。本页说明代码已经实现什么，以及使用者部署时需要自行完成什么。产品定位以[品牌规范](brand.md)为准。

## 结论摘要

Ingot 的主要软件流程已经实现，包括现场数据接入、运行比较、工艺追因，以及直接从真实配方运行生成、需要工程师确认的下一配方建议。

仓库只声明代码、数据库契约、自动化测试和可复现的软件行为，不内置特定场景的验证数据、历史协议或效果结果。

- **仓库负责**：软件能力、约束、权限、审计、失败关闭和部署参考实现。
- **使用者负责**：数据质量、场景适用性、工艺安全、配方采用和实际收益评估。

## 已实现的软件能力

当前仓库已经覆盖：

- 连接现场数据源，统一字段和单位，并在断网后恢复补传；
- 把设备、产品、工艺规范、材料、工装、过程曲线和质量结果关联到同一次运行；
- 检查数据是否完整、是否来自实际执行值、单位和版本是否明确；
- 比较满足可比条件的运行，显示关键差异、候选原因、反证和证据缺口；
- 自动把符合准入要求的真实配方运行与质量结果组成优化观察；
- 在安全边界和已观察参数包络内生成不会自动下发的下一配方建议，并追加冻结工程师的采用、修改或拒绝、原因、实际配方和关联运行；
- 根据数据条件选择响应面或高斯过程等方法，并在证据不足时降级；
- 保存建议使用的证据、约束、模型版本、工程师决定，并从实际运行、参数回读和检验记录一次性冻结最终结果；
- 提供有权限限制的分析助手：结构化生产事实由授权工具查询，已复核工艺文档可在项目和适用范围内进行关键词与可选语义混合检索，并返回片段级引用；同时提供备份、恢复、监控和基础故障演练工具。

“已实现”表示仓库中存在代码、数据库契约和测试，不表示适合任意工艺或已经产生特定业务收益。当前仓库也不声称已完成检索质量基准或证明文档检索能够缩短现场分析周期。

## 仓库验证边界

仓库不附带公开或现场效果数据、预设轮次协议、结果轨迹和效果报告。优化器单元测试覆盖算法契约、确定性、约束和失败关闭；具体场景的效果比较在使用者自己的环境中完成。

## 使用者责任

使用者负责：

- 定义目标、可调参数、安全约束和可接受风险；
- 保证运行、配方、过程数据和质量结果的身份与时间关系可靠；
- 使用自己的数据比较适用基线并确定验收门槛；
- 审核、采用或拒绝配方建议；
- 评估实际质量、成本、周期和生产安全影响。


## 生产部署边界

默认 Docker Compose 适合本地开发和单机参考部署，不代表正式生产要求已经完成。生产使用仍需配置密钥、身份和站点隔离，并完成备份恢复、容量、告警、设备联锁、人工审批、停止和恢复演练。

目标拓扑见[生产架构](production-architecture.md)，当前操作步骤见[部署运维](deployment.md)。
