# 当前状态

> 文档状态：**滚动事实页**。本页是“代码已经实现什么、验证已经证明什么、生产部署还缺什么”的统一入口。产品定位以[品牌规范](brand.md)为准，详细方法结果以[公开验证记录](https://github.com/liuweichaox/Ingot/blob/main/tools/public-validation/README.md)为准。

## 结论摘要

Ingot 的主要软件流程已经实现，包括现场数据接入、运行比较、工艺追因，以及直接从真实配方运行生成、需要工程师确认的下一配方建议；受控验证是独立的可选流程。

软件流程可运行不代表真实收益已经得到验证。当前策略尚未通过独立的未见数据验收，真实工厂的正式历史复盘和前瞻验证尚未完成。

- **已确认**：软件能够整理可追溯的运行证据，并在数据和安全条件满足时给出候选工艺设置。
- **尚未确认**：系统能够在真实工厂稳定减少实验、缩短研发时间或降低生产风险。

## 状态总览

| 层级 | 当前状态 | 可以得出的结论 |
|---|---|---|
| 合成演示 | 可运行 | 可以体验主要页面和业务流程 |
| 软件链路 | 已实现并有自动化测试 | 主要功能可以按设计运行；条件不满足时会停止建议并说明原因 |
| 公开方法回放 | 已做过多轮测试；当前方法待重新验收 | 可以查看方法的成功和失败，但不能把旧结果当成当前方法已经通过 |
| 真实历史回放 | 工具已具备，正式报告未完成 | 尚未正式证明系统在复盘旧项目时不会提前看到未来结果 |
| 前瞻影子验证 | 工具已具备，结果未完成 | 尚未证明建议在新项目中持续可靠；影子建议不会影响实际决策 |
| 受控在线验证 | 工作流和门禁已实现，结果未完成 | 尚不能证明真实工厂收益或因果效果 |
| 生产运行 | 提供单机参考部署 | 正式生产仍需完成高可用、恢复、安全和容量验收 |

## 已实现的软件能力

当前仓库已经覆盖：

- 连接现场数据源，统一字段和单位，并在断网后恢复补传；
- 把设备、产品、工艺规范、材料、工装、过程曲线和质量结果关联到同一次运行；
- 检查数据是否完整、是否来自实际执行值、单位和版本是否明确；
- 比较满足可比条件的运行，显示关键差异、候选原因、反证和证据缺口；
- 自动把符合准入要求的真实配方运行与质量结果组成优化观察，无需用户另建实验；
- 在安全边界和已观察参数包络内生成不会自动下发的下一配方建议；
- 必要时设计带对照、重复和安全边界的受控验证，并审核候选工艺操作域；
- 根据数据条件选择响应面或高斯过程等方法；复杂方法不合适时自动降级；
- 保存建议使用的证据、约束、模型版本、工程师审核和最终结果；
- 提供有权限限制的分析助手，以及备份、恢复、监控和基础故障演练工具。

“已实现”表示仓库中存在代码、数据库契约和测试，不表示某个工厂已经完成数据、性能、安全或收益验收。

## 公开方法证据

公开数据测试回答的是“在一组已经知道所有结果的实验中，系统能否按正确顺序更快找到目标”，它不能代替真实工厂试点。目前可以得出三点：

- 系统在部分测试中比随机试错更快；
- 在另一些测试中，它没有稳定胜过更简单的响应面方法，因此整体验收没有通过；
- 算法之后已经修改，旧数据只能用于开发检查，不能再作为当前方法的独立证明。

当前方法还需要在一组开发期间没有看过的新数据上重新验收。

完整协议、数字、置信区间和失败分项只在[优化器实验效率验证](https://github.com/liuweichaox/Ingot/blob/main/tools/public-validation/README.md)及其审计文件中维护。

## 真实项目证据

真实项目按以下顺序推进，每一步只回答一个问题：

```text
历史复盘（旧项目能否正确重放）
→ 影子验证（新建议是否持续合理，但不影响工程师）
→ 受控在线（实际采用建议是否安全且有价值）
→ 第二场景（换一种工艺后是否仍然适用）
```

这四步目前都还没有形成可以对外声称“已通过”的正式结果。真实生产数据、项目和设备标识、参数分布及计算结果留在受控工厂环境；公开数据测试不能替代这些证据。

具体验收问题、预注册内容和否证条件见[场景验证](rollout.md)。

## 生产部署边界

默认 Docker Compose 适合本地开发验证和单机参考部署，不代表已经达到正式生产要求。生产使用仍需完成：

- 密钥、身份、站点隔离和最小权限配置；
- 备份恢复、可接受的数据丢失与恢复时间目标、故障切换和连续观察；
- 实际负载下的容量、积压、延迟和保留策略验收；
- 对象存储、按时间点恢复、高可用和外部依赖故障方案；
- 设备侧联锁、人工审批、停止和回退演练。

目标拓扑见[生产架构](production-architecture.md)，当前操作步骤见[部署运维](deployment.md)。

## 状态更新规则

状态变化必须对应可复核证据：

1. 软件能力以合并的代码、数据库迁移和自动化测试为准；
2. 方法效果以预注册、冻结、未见数据和完整失败记录为准；
3. 真实项目价值以历史、影子和在线阶段各自的审核报告为准；
4. 生产成熟度以目标站点实际完成的恢复、容量、安全和观察证据为准。

API 存在、演示可运行或内部基础设施完成，都不能自动提升更高一层状态。
