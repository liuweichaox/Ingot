# Use cases

Ingot organizes analysis around common production questions that need operating context. Every use case starts from the production history and places outcome changes beside the corresponding process records.

## Why did yield change?

After a team selects the target batch and comparison baseline, Ingot summarizes first-pass yield, defect types, and impact scope, then compares process differences by station, process stage, equipment, or recipe.

The result covers:

- the batch where the change began;
- the station or stage where the difference is concentrated;
- process parameters that changed with the outcome;
- missing records and the number of workpieces covered by the comparison.

## Why do machines differ on the same recipe?

Ingot groups production cycles with the same recipe, nearby time range, and matching product, then compares cycle time, key parameters, inspection distributions, and anomaly frequency across machines.

Teams can identify persistent machine offsets, time-specific changes, and tooling or maintenance records that need further review.

## When should tooling be serviced?

The production history links tooling, molds, or cutters to each run. Ingot shows how quality metrics and process features evolve by usage count or accumulated operating time.

Teams can see remaining operating room, recent degradation rate, and the affected product scope when planning maintenance.

## What happened to one abnormal workpiece?

Starting from a workpiece or inspection result, Ingot reconstructs the related batch, machine, recipe version, tooling, process stages, and inspection records.

Engineers can review the timeline around the anomaly and compare it with normal workpieces from the same batch or similar historical cycles.

## What changed after a process adjustment?

Teams define before-and-after windows, product, equipment, and evaluation metrics. Ingot presents process features, quality results, and data coverage using the same definitions, making the adjustment easier to review and preserve as an investigation record.

## Is the data sufficient for analysis?

Before comparison, Ingot checks cycle completeness, time order, required context, inspection coverage, and comparable samples. Data-quality results appear beside business metrics so engineers can see the scope covered by the conclusion.
