# 工艺改进闭环

Ingot 将工艺改进拆成可以独立检查的五层。系统管理数据版本、计算结果、流程状态和人员操作记录；工厂负责提供真实数据、设备边界、质量目标以及现场审批。

## 分层能力

| 层级 | 系统能力 | 进入下一层的条件 |
|---|---|---|
| L1 数据可用 | 标准生产事件、周期、配方、工装、质量结果 | 周期标识一致，时间戳和运行信息完整 |
| L2 可比较分析 | 按阶段对齐、`cycle_phases`、`cycle_features`、迟到事件失效、历史回填、数据库特征汇总 | 分析方案和数据模型版本明确，阶段与采样质量达到使用要求 |
| L3 模型运行 | 训练数据版本、模型版本、评估门槛、启用、漂移、自动暂停、停用与回退 | 至少一条通过门槛的评估；同一模型只有一个运行版本 |
| L4 受控改进 | 调查、可能原因、参数边界、安全约束、受控试验、实际结果和结论 | 试验已批准并完成，结果通过安全检查，结论引用对应结果 |
| L5 审批执行 | 带适用范围、预期结果、风险、停止规则和回退方案的参数建议；复核、批准、外部执行编号和效果确认 | 已确认的调查结论；创建、复核和批准职责分开；实际效果和安全检查已记录 |

L5 表示软件已经具备受约束的决策闭环，不表示某一条建议天然正确，也不表示系统可以绕过现场安全制度自动修改设备。

## 周期物化、回填与数据库汇总

已完成周期的分析结果由以下身份共同确定：

- 周期号；
- 算法版本；
- 工艺数据模型及版本；
- 分析方案及版本；
- 源事件最高摄入编号和事件数量。

新事件到达后，相关周期会被标记为待重算并进入后台重算队列；完成周期会自动重新计算。服务启动和定时扫描会重新加入尚未处理的待重算周期，查询时仍保留确定性重算作为兜底。`POST /api/v1/cycle-analysis-backfills` 创建后台回填任务，任务记录总数、处理数、物化数、失败数和最后周期号；服务重启后会继续未完成任务。

窗口边界、连续阶段分组以及均值、极值、极差、标准差、P05/P50/P95、积分和斜率由 PostgreSQL/TimescaleDB 的窗口函数和聚合函数直接计算。实时迟到事件重算与历史批量回填共用同一个数据库计算器、算法版本和特征定义。每次物化还会用独立的应用内参考实现复算并按相对误差门禁比较；计算结果不一致时拒绝写入 `ready`，从而避免“流式一套、批式一套”。该实现不依赖 TDengine。

`GET /api/v1/cycle-feature-aggregates` 在 PostgreSQL 中对仍处于 `ready` 状态的物化结果计算周期数、最小值、最大值、平均值、标准差以及 P10/P50/P90，避免把大量特征行拉回应用内再聚合。

## 模型生命周期

训练数据版本一旦登记便不可覆盖。它保存分析方案版本、数据模型版本、时间范围、周期号、输入特征、目标数据项、行数和内容哈希。

模型版本从草稿开始。模型输入必须来自训练数据版本，输出必须与目标数据项一致。进入 `validated` 或 `active` 前必须登记模型产物位置和 SHA-256，并存在通过门槛的评估。漂移记录达到停用门槛时，运行模型自动进入 `suspended`。回退操作会停用当前版本并启用一个已有通过评估的版本。

主要接口：

- `GET|POST /api/v1/training-datasets`
- `GET|POST /api/v1/process-models`
- `POST /api/v1/process-models/{modelId}/{version}/evaluations`
- `POST /api/v1/process-models/{modelId}/{version}/drift`
- `POST /api/v1/process-models/{modelId}/{version}/status`
- `POST /api/v1/process-models/{modelId}/rollback`

## 调查和受控试验

一条调查依次保存：

1. 问题、适用范围和关联周期；
2. 可能原因、参数或信号、工艺阶段和方向；
3. 参数当前值、试验值、允许范围、安全约束、停止规则和回退方案；
4. 基准与试验结果、样本数、区间和安全检查；
5. 确认、排除或暂不确定的结论。

试验创建人不能批准自己的试验。未运行的试验不能记录结果，没有结果或安全检查未通过的试验不能完成，未完成的试验不能形成结论。

试验分为两种严谨度：

- `exploratory`：用于调查和小样本探索，可以由工程师登记结果，但不能冒充验证性科研结论。
- `confirmatory`：必须在批准前预注册预期作用、主要指标、信号/阶段/特征、改善方向、显著性水平、估计方法、计划样本量、分配方法、排除规则和安全指标绑定。基准组与试验组周期不得重叠。

验证性试验通过 `POST /api/v1/process-investigations/trials/{trialId}/results/calculate` 计算结果。系统只读取状态为 `ready`、且含特征定义哈希和计算哈希的周期物化结果，执行 Welch 组间均值差估计，计算标准误、自由度和双侧置信区间；安全约束也从绑定的周期特征计算。阶段指标必须指定阶段序号；基准组和试验组的单位、特征定义、算法版本、数据模型版本和分析方案版本必须完全一致，否则拒绝比较。结果校验哈希覆盖预注册协议、组别、周期号、特征值和每个特征的计算哈希。验证性试验拒绝人工结果，并且没有源数据校验哈希时不能完成。

## 机理模型与四种融合方式

机理模型按“模型标识 + 固定版本”注册，记录变量、单位、有效范围、适用工况、公式说明、来源和内容哈希。模型经过 `draft → validated → active → retired` 状态门禁，同一模型只允许一个活动版本。当前确定性执行器支持带截距和交互项的仿射机理模型。

融合定义绑定一个明确的机理模型版本和数据模型版本，并提供四种可复现方式：

- `calibration`：用数据模型对机理输出作偏差校准；
- `post-processing`：由机理模型修正数据模型输出；
- `mechanism-as-feature`：把机理输出作为数据模型的一个输入特征；
- `ensemble`：按登记权重合并机理与数据模型输出。

执行前校验变量、单位、有效范围和适用工况；执行结果保存两个分量、最终输出、执行哈希和审计记录。主要接口为 `GET|POST /api/v1/mechanism-models`、模型状态接口、`GET|POST /api/v1/mechanism-fusions` 及 `/execute`。

## 文档、表格、图片与现场知识

`POST /api/v1/process-knowledge` 接收 PDF、XLSX/XLSM、CSV、文本和常见图片格式。上传后自动解析：PDF 记录页码和整页定位，Excel 记录工作表与单元格范围，图片通过可配置视觉 OCR 服务记录多边形区域和置信度。每条记录同时保存提取器版本和内容哈希，可由 `/extract` 重新执行失败任务。服务端计算原文件 SHA-256，保存原文件，并可同时写入独立归档卷。

来源按 `uploaded → indexed → reviewed → retired` 流转。进入 `reviewed` 前，至少需要一条知识记录，且每条记录都必须完成人工复核。AI 或解析程序可以生成待复核记录，但不能代替现场人员完成复核。

图片 OCR 使用 `KnowledgeExtraction:Vision:Endpoint` 和 `KnowledgeExtraction:Vision:ApiKey`；未配置时图片来源保留为可重试失败状态，不伪造识别结果。

## 跨行业科研验证

`POST /api/v1/scientific-validation` 接收原始 CSV、XLSX/XLSM 或 MATLAB Level 5 MAT 文件及版本化数据清单。系统核验来源、许可、引用、原文件 SHA-256、字段覆盖、时序、真实测量声明和独立流批统计；任一硬门禁失败即将报告标为 `rejected`，不能用于科研结论。清单可登记有文献或设备说明支撑的信号有效范围，超界样本不会静默删除，其数量和判定说明会写入报告。

仓库中的 `docs/validation/datasets` 提供两个真实数据清单：

- NASA/UC Berkeley 铣削刀具磨损：167 次加工运行、16 个工况、6 类传感信号和间歇测量的后刀面磨损；
- Mendeley Al-Ce 时效热处理：516 条实测记录，包含温度、时间、硬度与电导率。

本地验收中两套数据均通过来源哈希和流批一致性门禁。它们证明的是导入、质量门禁和跨行业计算链可复现，不等同于已经证明任何具体工艺参数具有因果改善效果；后者仍需预注册试验和现场验证。

## 参数建议和设备边界

参数建议只能来自 `confirmed` 调查结论。建议参数必须已经出现在该结论关联的受控试验中，建议值必须等于已完成试验值，允许范围不能超出试验边界；其他值必须先做新的受控试验。预期结果必须与试验结果一致，运行约束不得弱于试验安全约束。建议同时包含：

- 适用产品、设备、配方或工装范围；
- 一个或多个参数设置；
- 运行和安全约束；
- 预期质量、成本、能耗或节拍结果；
- 预期年度经济价值、试验成本、实施成本、风险金额和计算说明；
- 风险说明、停止规则和回退方案。

正常状态为 `draft → reviewed → approved → executed → verified`。创建人不能复核自己的建议，批准人必须不同于创建人和复核人。`executed` 只记录 MES、变更单或设备侧编号；Ingot 不从该接口直接写 PLC。效果确认必须记录每个预期指标的实际值和样本数，以及经济价值观察窗口、观察期产生价值、实施成本和计算说明；净价值由系统按“产生价值减实施成本”计算，不能由客户端自行指定。系统根据预期改善方向自动判断目标是否达到，并从各指标安全检查计算总结果。任一目标未达到或安全检查失败时，状态自动进入 `rollback-required`；完成现场回退并填写外部回退编号后进入 `rolled-back`。

## 权限与部署

读取需要 `quality.read`。写入、状态转换、回填和审批需要 `process.engineer` 或 `platform.admin`。生产环境必须配置统一身份提供方，并为质量附件和工艺知识分别配置独立归档路径。

Web 入口位于“分析中心 → 工艺改进”。
