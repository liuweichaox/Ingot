# 配方优化试点指南

> 文档状态：**当前操作指南**。本文验证已实现的生产证据推荐流程，下一配方建议要求符合准入条件的生产运行证据。每次运行就是一次实验，实际参数和质量结果沿用运行证据链，完整能力边界见[当前状态](status.md)。

## 试点范围

限定一个产品或工艺范围和质量目标。为当前生产证据流程提供真实配方运行、实际参数、过程上下文和质量结果；数据可以来自人工操作或部署者配置的可选连接器。先验证身份、单位、来源和质量复核是否可靠。

## 操作顺序

1. 在工艺配置中打开已发布配方版本。页面从该版本、工艺变量、已发布质量方案和已有运行推导站点、产品范围、质量目标及可调参数；先检查这些来源配置和页面显示的范围是否正确，不另填一套试验变量。
2. 点击“检查数据”，查看范围内已完成运行中哪些通过准入，以及被排除的原因。配方需要带单位和上下界的可调参数、覆盖该配方的数值质量指标，以及已发布且包含过程曲线的过程分析。
3. 至少三条有效运行覆盖两种不同实际配方后，点击“生成下一轮校正”。这是最低数据门槛；覆盖、约束和方法检查不通过时仍会停止建议并说明原因。
4. 工程师选择“采用为下一轮校正”“修改后作为下一轮校正”或“拒绝”。修改和拒绝必须填写原因；直接采用保留建议参数，原因可选。采用或修改不改变已发布配方版本；显著变更使用“作为显著变更”打开修订草稿。
5. 采用或修改后，让后续真实运行沿用该配方版本。配方页面会尝试关联决定之后开始、已完成的下一条同版本运行；服务端仍校验站点和冻结的上下文。拒绝建议不要求关联运行。
6. 页面从已关联运行读取参数回读和检验事实并请求冻结结果；失败时修复数据后点击“再次读取结果”。只有通过结果准入的运行才进入后续优化观察。
7. 完成本轮决定与结果后，再生成下一轮校正。建议不会自动下发设备，现场参数调整仍按既有操作流程执行。

## 每次建议的检查

- 输入运行、质量结果和上下文是否可追溯。
- 建议是否在声明的安全边界与已观察覆盖内。
- 工程师决定是否记录采用、修改或拒绝；修改和拒绝是否填写原因。
- 采用或修改后是否关联了实际运行。
- 结果是否只在参数回读和检验事实齐备后冻结。

## 不足样本或异常数据

样本不足时继续正常生产并等待新的真实运行，或修复数据链。数据缺失、运行不可比、约束冲突或模型条件不满足时，不应绕过停止原因生成建议。

## 试点完成标准

试点至少完成一次可审计的“建议—决定—实际运行—质量结果”链路。它证明的是系统流程和本场景数据链可用，不自动证明任何通用收益或因果结论。
