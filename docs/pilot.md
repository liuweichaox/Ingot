# 配方优化试点指南

> 文档状态：**当前操作指南**。首个试点围绕一条真实生产证据闭环展开。

## 试点范围

限定一个产品、设备范围和质量目标。接通真实配方运行、实际参数、过程上下文和质量结果；先验证身份、单位、来源和质量复核是否可靠。

## 操作顺序

1. 在研发项目中定义产品范围、质量目标、可控变量和安全边界。
2. 让范围内已完成的真实配方运行自动进入准入检查。
3. 当至少三条有效运行覆盖两种不同实际配方时，生成一份下一配方建议。
4. 工程师记录采用、修改或拒绝，以及对应原因和最终实际配方。
5. 将后续真实生产运行关联到该决定；拒绝建议不需要虚构运行。
6. 参数回读和检验事实齐备后，从源数据冻结质量结果。
7. 让新的真实运行和结果独立回流，形成下一轮观察与建议。

## 每次建议的检查

- 输入运行、质量结果和上下文是否可追溯。
- 建议是否在声明的安全边界与已观察覆盖内。
- 工程师决定是否包含采用、修改或拒绝及原因。
- 采用或修改后是否关联了实际运行。
- 结果是否只在参数回读和检验事实齐备后冻结。

## 不足样本或异常数据

样本不足时继续正常生产并等待新的真实运行，或修复数据链。数据缺失、运行不可比、约束冲突或模型条件不满足时，不应绕过停止原因生成建议。

## 试点完成标准

试点至少完成一次可审计的“建议—决定—实际运行—质量结果”链路。它证明的是系统流程和本场景数据链可用，不自动证明任何通用收益或因果结论。
