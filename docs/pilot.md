# 配方优化试点指南

> 文档状态：**当前操作指南**。本文说明如何用已实现的生产证据推荐流程完成一次试点；下一配方建议要求符合准入条件的生产运行证据。每次运行就是一次实验，实际参数和质量结果沿用运行证据链。完整能力边界见[当前状态](status.md)。

## 试点范围

限定一个产品或工艺范围，以及一个质量目标。试点需要真实配方运行、实际参数、过程上下文和质量结果；已有可靠现场来源时，可由现场适配器采集并映射数据，通过 Edge 缓冲和补传事件，其他来源仍可人工录入或关联外部记录。开始前先确认身份、单位、来源和质量复核可靠。

## 操作顺序

开始前确认三件事：当前账户能读取目标工厂/生产现场的运行与检验记录；配方版本、质量方案和过程分析已发布；变量代码、单位及上下界一致。明确现场调整、质量录入与复核的责任人；要求独立复核时，录入人与复核人必须分开，并保留既有安全操作与审批要求。若这些条件不满足，先修复源配置，不要把试点当作配置绕行入口。

1. 在“配置与接入”中打开已发布配方版本。页面从该版本、工艺变量、已发布质量方案和已有运行推导工厂/生产现场、产品范围、质量目标及可调参数；先检查这些来源配置和页面显示的范围是否正确，不另填一套试验变量。
2. 点击“检查数据”，查看范围内已完成运行中哪些通过准入，以及被排除的原因。配方需要带单位和上下界的可调参数、覆盖该配方的数值质量指标，以及已发布且包含过程曲线的过程分析。
3. 有至少三条有效运行和两种实际可调参数组合时，点击“生成下一轮校正”。这是最低数据门槛。覆盖、约束和方法检查不通过时仍会停止建议并说明原因。
4. 工程师选择“采用为下一轮校正”“修改后作为下一轮校正”或“拒绝”。修改和拒绝必须填写原因；直接采用保留建议参数，原因可选。采用或修改不改变已发布配方版本；显著变更使用“作为显著变更”打开修订草稿。
5. 采用或修改后，让后续真实运行沿用该配方版本。配方页面会列出决定之后开始的同版本已完成运行，由工程师选择实际执行了这轮参数的一条。服务端仍校验工厂/生产现场和冻结的上下文。拒绝后保留决定并结束本轮。
6. 页面从已关联运行读取参数回读和检验事实并请求冻结结果。失败时修复数据后再次读取。冻结时会核对实际参数与决定参数的偏差。未按决定执行的结果保留为追溯记录，不计入该轮验证。该运行能否形成后续观察，仍取决于实际参数和观察准入规则。
7. 完成本轮决定与结果后，再生成下一轮校正。建议不会自动下发设备，现场参数调整仍按既有操作流程执行。

## 每次建议的检查

按操作顺序核对完成标志：

1. **范围确认**：页面范围与已发布源配置一致，目标和可调参数可逐项核对。
2. **数据确认**：能定位有效运行与被排除运行；有效数量达到门槛且实际参数至少有两种组合。
3. **建议生成**：取得可回看的建议记录，核对冻结条件、预测和约束。参数按步长对齐时，按[观察覆盖包络](optimization.md#观察覆盖包络)单独核实最终设置的联合覆盖和预测适用性。若生成停止，保留原因。
4. **决定记录**：采用、修改或拒绝已保存，修改后的参数与原因可核对；显著变更进入修订草稿。
5. **运行关联**：采用或修改关联到决定后开始的同版本真实运行，并通过服务端上下文校验；界面展示候选运行，由工程师确认实际执行。
6. **结果冻结**：参数回读和有效检验来自关联运行；实际参数与决定参数在容差内时计入该轮验证，超出容差时保留追溯记录但不计入；读取失败时保留原记录并补齐数据。
7. **本轮关闭**：本轮决定和所需结果完整，可再发起下一轮；拒绝路径不强行创建运行结果。

## 不足样本或异常数据

样本不足时继续正常生产并等待新的真实运行，或修复数据链。数据缺失、运行不可比、约束冲突或模型条件不满足时，不应绕过停止原因生成建议。

## 试点完成标准

归档本轮配方版本、输入运行标识、建议标识、工程师决定和关联运行，并记录排除或停止原因。复核者应能从这些标识回到原始参数与质量事实；若只能看到预测而无法回看实际运行，本轮尚未达到完成标准。

试点至少完成一次可审计的“建议—决定—实际运行—质量结果”链路。它证明的是系统流程和本场景数据链可用，不自动证明任何通用收益或因果结论。

## 现场评估与数据保密

- **固定比较口径**。在看结果前记录工艺范围、配方版本、质量规格、时间窗口、纳入和排除规则、成本口径及比较基线。基线可用同范围既有做法或适用的简单方法。先检查证据完整性、决定追溯和约束，再比较达到规格的运行数、质量或成本。纳入决定分布并单独解释未完成、被排除或被拒绝的记录。条件变化时重新判断可比性。
- **按时间回放**。冻结数据、随机种子、软件及算法配置版本。每一步只使用当时可见的运行、检验和知识来选候选、计算特征、处理缺失值和调参。把调参数据与最终比较数据分开，复用时记录限制。历史回放用于检查方法和软件行为。现场效果用真实后续运行评估。
- **预设停止条件**。出现安全边界异常、质量事实不可核实、可比性丢失、约束冲突或证据不足时，暂停建议并记录时间、关联运行和恢复依据。保留基线、版本、结果、缺失项和限制。证据不足时可得出需补充数据或暂不适用的结论。评估记录由部署者在受控环境中保存。
- **保护现场数据**。真实生产数据、项目与设备标识、工艺参数、质量分布、逐次运行轨迹和派生结果不进入公开仓库。部署者负责数据授权、保留、导出、备份与删除。
