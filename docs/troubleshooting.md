# 故障排查

本页面向本地安装与部署维护者。先确定故障发生在哪个服务，再处理配置或数据问题。首次安装步骤见[快速开始](getting-started.md)，恢复与升级要求见[部署运维](deployment.md)。

## 收集诊断信息

在仓库根目录运行以下只读命令：

```bash
git rev-parse --short HEAD
docker compose version
docker compose -f docker-compose.app.yml ps -a
docker compose -f docker-compose.app.yml logs --tail=200 platform-migrate platform-api platform-worker optimizer platform-web
```

记录故障发生时间、访问 URL、操作步骤、响应状态码和服务名。日志可能包含业务内容或首次管理员口令；分享前移除凭据、令牌、用户和现场标识。不要公开完整的 `docker compose config` 输出或 `.env`。

## Compose 配置校验失败

**症状**：`config --quiet` 或启动命令提示变量未设置。

**处理**：从当前版本的 `.env.example` 核对必填项，尤其是数据库密码、站点身份、Edge 身份及相关令牌。默认 Compose 的 API 需要这些绑定，即使未启动现场连接器。替换示例占位后重新校验：

```bash
docker compose -f docker-compose.app.yml config --quiet
```

**完成条件**：命令成功退出。它只检查 Compose 配置，不验证密码强度、网络连通或数据完整性。

## 容器启动后不健康

**症状**：服务为 `unhealthy`、反复重启，或页面连接失败。

1. 用 `ps -a` 确认具体服务。先查 `postgres`，再查 `platform-migrate`；迁移必须成功退出，API 和 Worker 才能正常启动。
2. 查看失败服务最近的日志。例如：

```bash
docker compose -f docker-compose.app.yml logs --tail=200 platform-migrate
docker compose -f docker-compose.app.yml logs --tail=200 platform-api
```

3. 镜像拉取出现 `unexpected EOF`、`short read` 或超时，检查 Docker 的网络与镜像访问，随后重试 `up -d --build`。
4. 数据库认证失败时核对配置与已有数据库卷的初始化身份。修改环境变量不会自动修改已有数据库用户密码。
5. 迁移报错时保留日志与备份，按具体迁移的要求处理旧数据。不要修改历史迁移或删除数据卷来绕过失败。

**完成条件**：迁移退出码为 0，基础持续运行服务通过健康检查，且不再反复重启。更完整的服务清单见[快速开始](getting-started.md)。

## 登录失败或接口拒绝访问

**症状**：无法登录、已有口令不匹配，或业务请求返回 401/403。

- 首次登录使用安装时配置的管理员身份。管理员引导只在用户表为空时执行；修改 `.env` 不会重置已有账户。
- 401 时检查会话、认证模式以及 OIDC issuer/audience；OIDC 回调和允许 origin 的配置见[部署运维](deployment.md)。
- 403 时检查岗位和站点授权。非管理员身份需要相应站点范围；读取某些运行详情还需要显式提供 `siteId`。
- 不要改为开发身份或放宽站点过滤来修复生产授权问题。

**完成条件**：目标身份可以访问已授权站点与岗位操作，并继续拒绝越权访问。

## 现场已采集但看不到完整运行

**症状**：节点在线，却没有预期运行、曲线或优化观察。

1. 核对 `SiteId`、`EdgeId`、令牌与设备身份是否一致。
2. 核对已发布采集配置实际应用状态，以及点位、工艺变量、单位和时间戳映射。
3. 区分事件接收、运行边界装配、过程分析和质量复核；成功接收事件不保证后续各阶段已经完成。
4. 检查 Worker 健康及后台任务错误，确认运行是否因身份、边界、必要字段或质量数据不完整被排除。

**完成条件**：同一运行身份能够追溯实际参数、过程轨迹、上下文和有效质量结果。按[数据接入](data-connection.md)核对接入链，不靠事后猜测补关联。

## 无法生成下一轮校正

**症状**：检查数据后没有有效样本，或建议被停止。

至少三条有效运行、两种不同实际配方只是最低门槛。还需核对已发布配方的可调变量、单位、步长和边界，覆盖配方的数值质量指标、过程分析，以及实际参数与经过所需复核的质量结果。覆盖不足、约束冲突和方法条件不满足也会停止建议。

已有未冻结校正时，先完成该轮决定和结果。数据不足时按提示修复证据链或收集更多真实运行。不要修改准入门槛来强行生成建议。

**完成条件**：数据检查通过；建议保留输入与证据范围，并在安全边界和观察覆盖内。详见[试点指南](pilot.md)与[分析与优化](optimization.md)。

## 助手或语义检索不可用

**症状**：自然语言回答失败，或语义检索未返回预期片段。

确认 Worker 状态、模型服务配置和所选协议。知识检索还需确认来源与片段已经复核，且属于当前授权站点和适用范围。语义嵌入默认关闭；启用后的配置与供应商接口要求见[部署运维](deployment.md)。

嵌入失败会回退关键词检索。没有通过授权、复核和范围检查的片段时，正确结果是证据不足。模型服务不可用时，运行与质量事实仍由原业务路径管理。

## 提交问题

提交 [Issue](https://github.com/liuweichaox/Ingot/issues) 时附版本、脱敏日志、复现步骤、预期与实际结果，以及已尝试的检查。不要附真实生产数据。安全漏洞使用[私密报告渠道](../SECURITY.md)。
