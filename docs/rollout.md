# 落地验证

Ingot 从一个真实工艺研发项目开始落地。第一阶段的目标是建立完整研发闭环，并用实验次数、研发时间或资源成本的变化验证产品价值。

## 1. 选择研发项目

首个项目应当具备：

- 明确的产品、材料和工艺对象；
- 可以量化的目标规格或研发指标；
- 一组能够调整的工艺参数；
- 清晰的设备和安全边界；
- 可以执行并检测结果的真实实验条件；
- 负责判断结果的工艺工程师。

项目开始时记录当前基线，包括以往达到规格所需的实验次数、日历时间、材料消耗、设备占用和人工投入。

## 2. 定义目标、变量和约束

工艺工程师在同一项目中确认：

| 内容 | 需要明确的信息 |
|---|---|
| 研发目标 | 指标、基线、目标值、方向、容差和完成条件 |
| 可控变量 | 参数名称、单位、上下界、步长和设置方式 |
| 过程变量 | 实际温度、压力、速度、位置、时间和阶段特征 |
| 结果变量 | 尺寸、面形、缺陷、强度、良率、效率或成本 |
| 上下文 | 材料、批次、设备、模具、配方、环境和人员 |
| 约束 | 设备能力、安全边界、变量耦合、停止和回退条件 |

## 3. 建立数据链路

实施团队完成主流协议驱动和具体设备适配，将现场点位映射为项目中的工艺变量。采集验证覆盖：

- 设备连接和地址读取；
- 原始值、缩放、单位和数据类型；
- 设备时间、Edge 时间和中心时间；
- 周期、阶段和实验关联；
- 缺失、重复、断线和恢复补传；
- 检测结果与实验运行对应关系。

少量真实实验首先用于确认数据链路和工艺语义，再进入连续研发。

## 4. 汇集历史证据

历史实验、过程数据、检测记录、工艺文件、物理机理和专家经验进入同一研发项目。系统标记数据来源、时间范围、适用条件、质量状态和版本，形成可复算的数据集快照。

## 5. 形成第一轮研发判断

系统完成：

- 数据质量与实验有效性检查；
- 周期和工艺阶段对齐；
- 关键时序特征计算；
- 变量分布、敏感性和交互分析；
- 历史结果与目标规格比较；
- 物理机理和专家规则核对；
- 候选研发假设和证据限制整理。

工艺工程师审核分析结果，确认可用于下一轮实验设计的目标、变量和边界。

## 6. 设计下一组实验

实验建议同时考虑：

- 接近目标规格的潜力；
- 对当前假设的信息增益；
- 已探索和未探索工艺区域；
- 模型不确定性；
- 材料、设备和安全约束；
- 实验成本、时间和可执行性。

每个候选实验说明推荐理由、参数组合、预期结果范围、不确定性、安全检查和验证目标，由工艺工程师审核后执行。

## 7. 执行、检测与更新

实验运行分别保存计划设置、实际设置、真实过程曲线和最终检测结果。系统评估计划偏差、数据完整性和实验有效性，并用新结果更新假设、模型、工艺空间和下一步建议。

这一过程持续迭代，直到满足目标规格和重复验证条件，或者达到项目预算与停止条件。

## 8. 验证工艺窗口

候选工艺窗口通过受控实验确认：

- 目标指标达到规定范围；
- 关键过程变量保持稳定；
- 安全指标全部通过；
- 独立重复实验具有一致结果；
- 适用材料、设备、模具和环境范围明确；
- 结果可以从检测记录追溯到真实过程和计算依据。

## 9. 沉淀工艺知识

经工程师审核的结论保存为版本化工艺知识，包括：

- 工艺规律和参数窗口；
- 适用范围与限制；
- 支持和反对证据；
- 数据集、实验、模型和机理来源；
- 风险、停止规则和复验要求；
- 审核人与验证时间。

这些知识用于后续产品、材料和设备的研发暖启动。

## 10. 衡量落地结果

首个项目完成后，对比项目基线：

- 达到目标规格的实验次数；
- 工艺研发日历时间；
- 无效实验比例；
- 材料、设备和人工成本；
- 推荐实验采用率和有效率；
- 参数窗口重复验证结果；
- 形成并复用的工艺知识数量。

落地完成的标准，是系统已经用真实数据和真实实验帮助工程师更快完成一次工艺研发，而不仅是设备已经连接或数据已经进入。
