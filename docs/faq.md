# 常见问题

> 文档状态：**当前产品与技术边界**。

## Ingot 最核心要解决什么？

让工艺研发从没有数据支撑走向有数据支撑，让计算机基于真实数据帮助工艺工程师抉择，并按问题选择有效计算方法。采集、分析、实验和优化都是实现这个目标的能力。

## Ingot 是数据采集系统吗？

不只是。采集是必要地基，但价值出现在数据被组织成一次真实运行的条件、轨迹和质量证据，并能够支持比较、判断和下一步实验时。

## Ingot 会取代工艺工程师吗？

不会。系统整理事实、执行计算、暴露不确定性并提出候选动作；工程师定义问题、审核数据和约束、判断现场可执行性、批准实验并承担最终决策。

## 系统能自动找到根因吗？

历史数据通常只能形成候选原因、稳定关联、混杂关联或证据不足。确定原因需要工程判断以及适当的对照、重复、区组、随机化或干预实验。Ingot 帮助缩小范围和设计验证，不把相关性直接冒充因果。

## 为什么需要 Manufacturing、Process Executions 和 Inspections？

Process Executions 定义一次真实运行，Manufacturing 保存这次运行的设备、产品、工艺规范、材料和工装条件，Inspections 保存结果。缺少其中任何一项，计算机都可能把不同条件的运行错误地混在一起。

## 为什么计划参数不够？

设备可能出现限幅、偏差、人工调整和动态响应。模型必须知道实际执行值。显式映射的实际值缺失时，运行被排除并显示原因，而不是用计划值补齐。

## 为什么过程曲线也重要？

相同设定可以产生不同升温速率、过冲、压力保持、位置和冷却轨迹。质量取决于真实过程，不只取决于工艺规范表。阶段特征帮助工程师定位偏差发生在哪里。

## 为什么记录材料、工装和设备上下文？

它们可能是重要影响因素，也可能只用于追溯。系统先检查覆盖和因素重叠，再决定能否估计影响；不会因为字段存在就自动把它加入模型。

## 为什么不始终使用最复杂的 AI？

因为最有效的方法取决于问题和数据。简单比较、稳健统计或一个良好设计的对照实验，可能比复杂模型更可靠。数据不足或因素不可辨识时，系统应建议补数据或拒绝回答。

## LLM 在系统里做什么？

LLM 理解问题、调用授权工具、组织记录和解释结果。它不直接生成数值工艺设定，不替代统计、约束和实验验证，也不能在没有来源时补造事实。

## 基础模型和 Agent 能力持续增强后，Ingot 的定位是什么？

不会变成通用工业聊天产品。长期目标是成为面向制造工艺的可信决策与验证操作系统：基础模型和 Agent 可以更换，但运行事实、证据关系、实验状态、权限审批、执行回执和结论边界由 Ingot 保持。近期先证明历史证据装置可信，中期开放模型无关的 Agent 能力，长期再发展制造智能的证据与实验开放规范。详见[战略规划与滚动路线图](project-plan.md)。

## 接入 MCP 就等于 Agent 可以安全驱动实验吗？

不等于。MCP 或类似协议解决工具怎样被发现和调用；项目隔离、来源引用、审批、幂等、动作白名单、设备确认和回滚仍必须由 Platform 与现场系统强制执行。Agent 从只读到提议、承诺和执行逐级开放，不能自批或直连设备。

## 什么时候适合贝叶斯优化？

当实验昂贵、响应带噪、可控变量数量有限、目标可量化、边界明确并且需要逐次选择实验时比较适合。高维、强漂移、质量反馈很慢或主要原因未测量的场景应先降维、补数据或使用其他方法。

## 数据很少怎样开始？

先完成安全基线和少量有信息量的初始实验。可以使用工程知识、经典 DOE、空间填充或安全区域内的探索。不要在没有安全证据时让算法猜测任意工艺规范。

## 能一次推荐多个实验吗？

可以在存在并行设备或批次效率要求时生成批量建议，并把尚未完成的条件作为 pending points。批量大小由现场执行方式决定，不把“推荐更多点”当成价值指标。

## 推荐会自动写入控制系统吗？

默认不会。建议先成为正式实验，由工程师审核后通过人工、MES、工艺规范管理系统或受控集成执行。设备联锁和现场安全规则独立于模型存在。

## Optimizer 或模型服务故障会停止采集吗？

不会。Edge、Platform、过程执行和检验记录继续工作；只暂停依赖该服务的新建议或自然语言解释。

## 为什么示例使用光学镜片模压和 FX3U？

它们是第一个可重复验证数据链和算法路径的场景，不是产品边界。更换工艺时需要新的变量、映射、目标、约束、上下文和可选机理知识，但不应重写证据主干和实验状态机。

## 系统已经证明能缩短研发周期吗？

尚未公开完成真实项目的历史回放和前瞻在线验证。代码能力不等于产品收益。项目会按照[真实场景验证](rollout.md)公布数据范围、基线、失败和局限后，才陈述量化效果。

## 文档是否已经定型？

核心价值、产品边界、证据原则和稳定架构已进入 v1 基线。算法、默认实验参数、菜单、实现状态、路线图和验证结果继续滚动更新，但不能重新定义核心价值或绕过证据边界。
