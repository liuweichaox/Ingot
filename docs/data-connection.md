# 数据接入

> 文档状态：**当前技术说明**。外部适配器负责现场通信和数据转换；Edge 接收、持久化并向 Platform 上报事件。

## 接入边界

Ingot 不内置设备协议驱动。设备、网关或已有采集程序的协议、采样频率、触发条件及 PLC 写入由现场适配器负责。适配器可以由工程师编写或使用 AI 辅助编写；投入使用前必须在目标环境核对实际数据、安全边界和故障处理。

需要设计适配器本地采集存储时，可参阅[现场采集数据参考设计](acquisition-data-design.md)：其中 `site_` 表是可选参考，不是 Ingot 已创建或强制要求的表；文中同时说明 Platform 已实现的点位、采样帧和值表。Edge 本地 SQLite 事件日志与 Platform 正式业务库分别存储。

已有采集程序可继续使用其点位配置，无需建立 `site_point_definition`；适配器负责核对编码、单位、来源与运行关联并转换为事件。Edge 提供认证的事件接收接口、本地持久化、上报和健康状态。Platform 是正式业务记录源，负责工厂隔离、事件接收和过程数据准入。Ingot 不因收到事件而控制设备，也不把接收成功视为工艺质量或优化效果已验证。

## 身份与数据语义

每个 Edge 绑定一个稳定的 `SiteId` 和独立 `EdgeId`。外部适配器须使用可靠的 `ExecutionId` 将同一次运行的事件、实际参数和检验关联起来；不得仅凭时间邻近猜测对应关系。适配器负责提供真实发生时间、来源、设备身份和工艺上下文，并将值转换为已发布工艺数据模型使用的编码、类型和单位。

`OccurredAt` 表示来源发生时间。Edge 记录接收时间并分配本地序号；Platform 的摄入时间是另一时间。断网补传时不得用到达时间代替发生时间。配方设定值不能冒充实际参数；缺失、异常和未知应保持可见。

## 向 Edge 提交事件

外部适配器向 `POST /api/v1/connector-events` 发送 JSON 事件数组，并使用 `Authorization: Bearer <ConnectorHost:IngestToken>`。凭据应由部署者安全提供，不应写入源码或示例报文。默认每批最多 1000 条，可通过 `ConnectorHost:MaxBatchSize` 配置，允许范围为 1–10000。

事件契约见 `src/shared/Ingot.Domain/Events/ProductionEvent.cs` 和 `ProductionEventValidator.cs`。`EventId` 必须是 UUIDv7；`EventType` 使用小写点分格式；`Subject` 必须有类型和标识；`OccurredAt` 必须有效。适配器提供稳定事件身份，重试前保留原始事件及其身份。Edge 检查并限制来源所属节点、生成事件摘要并持久化，返回接收事件的标识和本地序号。

对 `process.sample`，`data.values` 必须是对象，键为已发布工艺数据模型中的数据项编码，值类型必须匹配模型，必填项不得缺失。Platform 还必须能根据事件上下文解析已发布模型。仅通过 Edge 的格式校验不代表事件已通过 Platform 准入。

事件仍保存在 Edge 本地日志期间，相同 `EventId` 和业务内容的重试返回原序号，不新增待传事件；同一标识用于不同内容时返回 HTTP 409，整批回滚。Edge 自动生成的记录时间、序号和摘要不参与比较。已确认事件可能按保留策略被清理，队列达到上限也可能丢弃最旧待传事件；清理或丢弃后不保证本地去重，适配器须监控并核对上报结果。[外部适配器示例](../examples/external-adapter/README.md)仅验证 Edge 接收，不证明平台准入或完整运行链路。

## 上报与故障处理

HTTP `202 Accepted` 表示该批已由 Edge 接受并写入本地事件日志，不表示 Platform 已接收或业务分析已经完成。队列达到硬上限时，即使返回 202，也可能在同一事务中丢弃最旧的待传事件，包括本批事件。Edge 在 Platform 确认后推进本地待传队列；部署者应监控健康状态、积压和拒绝，并为持久目录提供足够空间与备份。适配器也应保留未被 Edge 接受的事件并处理重试及错误。

原事件被本地清理或丢弃后，不要盲目重发同一 ID：Edge 可能赋予新序号并返回 202，而 Platform 可能因该 ID 已存在但序号或摘要不同而拒绝并隔离事件。应先核对 Platform 接收记录和 Edge 隔离记录，再按现场恢复流程处理；当前没有跨清理周期的端到端幂等保证。

每个 Edge 实例必须使用独立持久目录。更换目录或丢失待传队列时必须更换 `EdgeId`，避免复用身份后本地序号重置。配置独立的接入、节点诊断和 Platform 上报凭据；部署与恢复步骤见[部署运维](deployment.md)。

## 验收

在目标环境至少验证：认证失败与无效事件被拒绝；一次真实运行及质量结果正确关联；点位值、类型、单位和时间与来源一致；短暂断网后事件恢复上报；重复提交、队列满和无效数据的处理符合现场要求。检查 Platform 的接收和数据质量状态，记录适配器版本、配置及测试结果。验收一个现场不代表其他设备或工厂已验证。
