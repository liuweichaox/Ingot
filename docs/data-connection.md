# 设备与数据接线

## 接线目标

优化器需要的不是一堆孤立点位，而是一条能回答以下问题的运行记录：

- 这次运行计划设置了什么？
- 实际运行采用了什么设置与条件？
- 周期轨迹真正怎样变化？
- 最终质量和安全结果是什么？

## 数据源与适配器

Ingot 不把 PLC 当作唯一数据入口。一次运行可以由以下任意组合构成：

- 控制系统的配方、状态和过程信号；
- 仪器、传感器或边缘网关的测量；
- 机器视觉、实验室或在线检验结果；
- MES、QMS、批次追溯或其他业务系统的运行上下文。

适配器的职责是把原始数据映射为稳定业务编码、单位、质量状态与 `RunKey`；研发项目不能绑定某个厂商地址或协议。

## FX3U 示例连接

FX3U 是一个已支持的现场控制器示例，使用 Edge 的 MELSEC A1E 采集运行器。它不是产品边界。该场景至少配置：

- PLC 地址和端口；
- 轮询周期；
- 周期开始、完成和相关标识；
- 配方寄存器；
- 温度、压力、位置等过程点；
- 数据类型、字节序、缩放和单位。

不要把设备地址直接写进研发项目。设备模板负责地址，研发变量只引用稳定业务编码。

## 驱动能力边界

每个通信驱动真正支持的配置项不同。平台维护一份能力矩阵，配置界面据此只显示会生效的字段，
校验器据此拒绝对该驱动无意义的配置——而不是接受之后在采集节点里静默丢弃：

| 能力 | HTTP 轮询 | MQTT | OPC UA | Modbus TCP | 三菱 1E |
|---|---|---|---|---|---|
| 采样时间取自设备 | ✅ | ✅ | ❌ 固定用服务器 SourceTimestamp | ✅ | ✅ |
| 序号字段 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 连接超时 | ✅ | ❌ | ✅ | ✅ | ✅ |
| 重连间隔 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 配方参数集合路径 | ✅ | ✅ | ❌ | ❌ | ❌ |
| 按主题绑定点位 | ❌ | ✅ | ❌ | ❌ | ❌ |
| 字节序 / 字序 | ❌ | ❌ | ❌ | ✅ | ❌ |
| 位寻址 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 探查能枚举点位 | ✅ | ✅ | ✅ | ❌ 只回读已配置寄存器 | ❌ 只回读已配置软元件 |

能力矩阵同时驱动配置界面和发布校验。新增驱动时先登记能力，界面与校验自动跟随。

## 点位选择器语法

### Modbus TCP

```text
<寄存器区>:<地址>:<类型>[:<字节序>:<字序>]
<寄存器区>:<地址>.<位>:boolean
```

寄存器区为 `holding-register`、`input-register`、`coil`、`discrete-input`。
线圈与离散输入是位区，类型只能是 `boolean`；从保持/输入寄存器取单个位需要写出位偏移。
字符串的第 4 段是字节长度而不是字节序。地址起点由连接参数决定：填手册地址（从 1 开始）时，
采集节点发送请求前自动减 1。

### 三菱 MC（A 兼容 1E 帧）

```text
<软元件>:<编号>:<类型>[:<字节长度>]
<字软元件>:<编号>.<位>:boolean
```

软元件编号按设备手册的进制书写：**X / Y 是八进制**（编号里不能出现 8 和 9），
**B / W 是十六进制**，其余十进制。配置界面会同时显示换算后的软元件号，便于对照手册确认第一次接线。

位软元件（M / X / Y / B / S / L）读取 `boolean` 时使用位单位批量读命令；
按 `int16` 之类的数值类型读取位软元件，拿到的是从该编号起 **16 个连续点打包成的一个字**，
不是单点状态。

该协议一次读取只覆盖一段连续软元件。相邻点位按连接参数中的合并间隔并成一次请求，
把 N 个点位的 N 次网络往返压缩成少数几次；把合并间隔设为 0 可退回逐点读取，用于排查某个软元件是否可读。

## MQTT 多主题

网关常常把一台设备的数据拆在多个主题上发布。此时：

- 每个订阅可以单独指定**报文根路径**，用于剥掉 `payload`、`d` 之类的信封；
- 每个点位可以绑定**来源主题**，留空表示接受任意主题的报文；
- 跨主题的值合并成一份等价快照后，走与单主题完全相同的映射与换算逻辑；
- 只有全部必需点位都收到过报文，才会产生采样；只携带上下文的主题会更新快照但不触发采样；
- 绑定到没有订阅的主题会在保存配置时被拒绝，而不是永远收不到数据。

订阅多个主题时应设置**值的最大陈旧时间**。某个主题停止发布后，合并快照默认会一直沿用它最后一次的值
并继续产生采样——这等于把过期数据当成当前状态。配置上限后，超时的值视为缺失，必需点位缺失即停止产生采样，
并在现场节点状态里说明还在等哪个主题。

## 周期相关标识

Platform 生成实验 RunKey，例如：

```text
bo-7d2f6a3e1c2d-01
```

如果现场控制器有周期相关寄存器，可把该值或可逆映射写入寄存器；采集事件使用它构建周期 `CorrelationId`，检验记录把它保存为 `OperationRunId`。没有 PLC 的场景，也可由 MES 工单、条码、仪器样本号或 Edge 映射关联到同一 `RunKey`。

如果控制器只能保存数值，可在 Edge 设备映射中维护短数字 ID 与 RunKey 的确定性关系。

## 数据来源表达式

### 控制变量

```text
recipe:<配方编码>
signal:<信号编码>:<特征编码>
signal:<信号编码>:<特征编码>:<阶段编码>
```

示例：

```text
recipe:holding-temperature
signal:mold-temperature:mean:holding
```

### 目标与结果约束

```text
inspection:<检验特性编码>
```

示例：

```text
inspection:form-error
inspection:crack-rate
```

## 过程特征

周期分析引擎按信号和阶段输出版本化特征，例如：

- 平均值、最小值、最大值和标准差；
- 斜率、积分、峰值和过冲；
- 到达时间、停留时间和阶段覆盖率；
- 实际升温速率、压力保持稳定性。

训练只使用所有有效观察共同存在的特征。增加或改变特征定义会改变版本与内容哈希。

## 有效观察条件

观察只有同时满足以下条件才进入模型：

- 周期已完成；
- 过程数据不是 unavailable；
- 至少存在一个过程特征；
- 每个可控变量都有实际值；
- 每个目标都有数值检验；
- 每个结果约束都有数值检验；
- 单位匹配；
- 数值有限。

排除运行仍保留来源哈希和原因，用于修复接线，而不是被静默丢弃。

## 换场景

换设备或工艺时优先新增配置，而不是复制代码：

1. 选择或实现协议驱动；
2. 建立设备模板和点位；
3. 定义周期与阶段；
4. 映射研发变量；
5. 定义检验特性；
6. 提供安全基线；
7. 用一个完整运行验证端到端关联。
