# 设备与数据接线

## 在业务闭环中的位置

设备接入不是第一步。先在工艺模型中定义平台需要理解的变量、类型和标准单位，再选择协议并把真实设备点位映射到这些变量：

```text
工艺定义 → 设备接入 → 生产采集 → 数据闭环 → 工艺追因 → 工艺优化
```

完成设备接入的判定标准不是“连接成功”，而是必需点位已经读取、换算并验证，生产开始和结束可以形成周期，实际配方与过程数据能够进入同一运行上下文。

## 接线目标

优化器需要的不是一堆孤立点位，而是一条能回答以下问题的运行记录：

- 这次运行计划设置了什么？
- 实际运行采用了什么设置与条件？
- 周期轨迹真正怎样变化？
- 最终质量和安全结果是什么？

## 数据源与适配器

Ingot 不把 PLC 当作唯一数据入口。一次运行可以由以下任意组合构成：

- 控制系统的配方、状态和过程信号；
- 仪器、传感器或边缘网关的测量；
- 机器视觉、实验室或在线检验结果；
- MES、QMS、批次追溯或其他业务系统的运行上下文。

适配器的职责是把原始数据映射为稳定业务编码、单位、质量状态与 `RunKey`；研发项目不能绑定某个厂商地址或协议。

## 工艺语义与设备接入的边界

工艺语义模型只定义平台要理解的变量代码、显示名称、标准类型、标准单位、用途和必需性，不包含设备地址、寄存器或采样频率。设备接入配置引用一个语义模型版本，再定义协议、点位、原始类型和换算规则。同一语义模型因此可以复用于 FX3U、OPC UA 或其他设备。

阶段号是用途为“阶段号”的普通工艺变量，只映射一次；Edge 从该变量自动生成阶段变化事件。生产开始/结束状态属于设备控制信号，在接入配置中单独映射。

## 按驱动配置，而不是填写通用地址

设备接入先选择通信驱动，页面再显示该驱动真正需要的参数。当前支持范围如下：

| 驱动 | 连接参数 | 点位参数 | 发现或验证方式 |
| --- | --- | --- | --- |
| HTTP 接口 | 服务地址、JSON 路径、轮询间隔 | JSON 字段路径、原始类型、换算 | 读取一次 JSON 并显示字段树 |
| MQTT | 服务器、端口、版本、客户端、登录、TLS、主题、QoS、会话方式 | JSON 字段路径、原始类型、换算 | 等待一条真实消息并显示字段树 |
| OPC UA | 端点、安全模式、安全策略、登录方式、证书、发布/采样间隔 | NodeId、换算 | 发现端点、浏览节点并读取当前值 |
| Modbus TCP | 主机、端口、Unit ID、0/1 基地址、轮询间隔 | 寄存器区、地址、类型、字节序、字序 | 只试读已配置地址，不盲扫寄存器 |
| 三菱 MC 1E | PLC 地址、开放端口、二进制/ASCII、目标站号、监视定时器 | 软元件、编号、类型、文本长度 | 只试读已配置软元件，不盲扫 PLC |

连接和点位是两层配置：连接层描述怎样到达设备；点位层描述读取哪里以及怎样解释原始字节。发布前必须完成真实连接和映射验证。

## FX3U 示例连接

FX3U 是一个已支持的现场控制器示例，使用 Edge 的 MELSEC A1E 采集运行器。它不是产品边界。该场景至少配置：

- PLC 地址和端口；
- 与 PLC 开放设置一致的 A 兼容 1E 帧、TCP 传输和二进制/ASCII 数据码；
- 目标站号和监视定时器；
- 轮询周期；
- 生产开始/结束状态和可选的设备循环计数；
- 配方寄存器；
- 温度、压力、位置等过程点；
- 软元件、地址、数据类型、缩放和单位。

不要把设备地址直接写进研发项目。设备模板负责地址，研发变量只引用稳定业务编码。

## 周期关联

Platform 生成实验 RunKey，例如：

```text
bo-7d2f6a3e1c2d-01
```

PLC 不需要提供 `CorrelationId`。Edge 检测到生产状态由停止变为生产时自动生成周期 `CorrelationId`，状态恢复停止时关闭该周期。这个内部标识串联周期开始、过程采样、阶段变化、配方快照和周期结束事件。

PLC 的循环计数、工件号、工单号或批次号应作为 `source_cycle_no`、`workpiece_id` 等业务上下文采集，而不是冒充 `CorrelationId`。MES、条码或检验系统可通过这些业务上下文与实验 `RunKey` 建立关联。

## 数据来源表达式

### 控制变量

```text
recipe:<配方编码>
signal:<信号编码>:<特征编码>
signal:<信号编码>:<特征编码>:<阶段编码>
```

示例：

```text
recipe:holding-temperature
signal:mold-temperature:mean:holding
```

### 目标与结果约束

```text
inspection:<检验特性编码>
```

示例：

```text
inspection:form-error
inspection:crack-rate
```

## 过程特征

周期分析引擎按信号和阶段输出版本化特征，例如：

- 平均值、最小值、最大值和标准差；
- 斜率、积分、峰值和过冲；
- 到达时间、停留时间和阶段覆盖率；
- 实际升温速率、压力保持稳定性。

训练只使用所有有效观察共同存在的特征。增加或改变特征定义会改变版本与内容哈希。

## 有效观察条件

观察只有同时满足以下条件才进入模型：

- 周期已完成；
- 过程数据不是 unavailable；
- 至少存在一个过程特征；
- 每个可控变量都有实际值；
- 每个目标都有数值检验；
- 每个结果约束都有数值检验；
- 单位匹配；
- 数值有限。

排除运行仍保留来源哈希和原因，用于修复接线，而不是被静默丢弃。

## 换场景

换设备或工艺时优先新增配置，而不是复制代码：

1. 选择或实现协议驱动；
2. 建立设备模板和点位；
3. 定义周期与阶段；
4. 映射研发变量；
5. 定义检验特性；
6. 提供安全基线；
7. 用一个完整运行验证端到端关联。
