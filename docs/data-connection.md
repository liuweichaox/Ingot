# 设备与数据接线

## 接线目标

优化器需要的不是一堆孤立点位，而是一条能回答以下问题的运行记录：

- 这一炉计划设置了什么？
- 实际运行采用了什么设置与条件？
- 周期轨迹真正怎样变化？
- 最终质量和安全结果是什么？

## 数据源与适配器

Ingot 不把 PLC 当作唯一数据入口。一次运行可以由以下任意组合构成：

- 控制系统的配方、状态和过程信号；
- 仪器、传感器或边缘网关的测量；
- 机器视觉、实验室或在线检验结果；
- MES、QMS、批次追溯或其他业务系统的运行上下文。

适配器的职责是把原始数据映射为稳定业务编码、单位、质量状态与 `RunKey`；研发项目不能绑定某个厂商地址或协议。

## FX3U 示例连接

FX3U 是一个已支持的现场控制器示例，使用 Edge 的 MELSEC A1E 采集运行器。它不是产品边界。该场景至少配置：

- PLC 地址和端口；
- 轮询周期；
- 周期开始、完成和相关标识；
- 配方寄存器；
- 温度、压力、位置等过程点；
- 数据类型、字节序、缩放和单位。

不要把设备地址直接写进研发项目。设备模板负责地址，研发变量只引用稳定业务编码。

## 周期相关标识

Platform 生成实验 RunKey，例如：

```text
bo-7d2f6a3e1c2d-01
```

如果现场控制器有周期相关寄存器，可把该值或可逆映射写入寄存器；采集事件使用它构建周期 `CorrelationId`，检验记录把它保存为 `OperationRunId`。没有 PLC 的场景，也可由 MES 工单、条码、仪器样本号或 Edge 映射关联到同一 `RunKey`。

如果控制器只能保存数值，可在 Edge 设备映射中维护短数字 ID 与 RunKey 的确定性关系。

## 数据来源表达式

### 控制变量

```text
recipe:<配方编码>
signal:<信号编码>:<特征编码>
signal:<信号编码>:<特征编码>:<阶段编码>
```

示例：

```text
recipe:holding-temperature
signal:mold-temperature:mean:holding
```

### 目标与结果约束

```text
inspection:<检验特性编码>
```

示例：

```text
inspection:form-error
inspection:crack-rate
```

## 过程特征

周期分析引擎按信号和阶段输出版本化特征，例如：

- 平均值、最小值、最大值和标准差；
- 斜率、积分、峰值和过冲；
- 到达时间、停留时间和阶段覆盖率；
- 实际升温速率、压力保持稳定性。

训练只使用所有有效观察共同存在的特征。增加或改变特征定义会改变版本与内容哈希。

## 有效观察条件

观察只有同时满足以下条件才进入模型：

- 周期已完成；
- 过程数据不是 unavailable；
- 至少存在一个过程特征；
- 每个可控变量都有实际值；
- 每个目标都有数值检验；
- 每个结果约束都有数值检验；
- 单位匹配；
- 数值有限。

排除运行仍保留来源哈希和原因，用于修复接线，而不是被静默丢弃。

## 换场景

换设备或工艺时优先新增配置，而不是复制代码：

1. 选择或实现协议驱动；
2. 建立设备模板和点位；
3. 定义周期与阶段；
4. 映射研发变量；
5. 定义检验特性；
6. 提供安全基线；
7. 用一个完整运行验证端到端关联。
