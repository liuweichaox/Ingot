# 机理知识设计

> 文档状态：**架构基线**。机理知识用于约束和解释建议，不创建第二条研发运行流程。

## 定位

机理知识把工程经验、工艺资料和来源证据保存为可审核、可版本化且带适用范围的资产。它可以解释建议、排除已知危险组合或调整候选排序；它不能替代真实生产运行、质量结果或工程师决定。

## 与建议闭环的关系

```text
知识来源 → 声明与约束 → 建议输入快照
真实运行与质量结果 → 优化观察 → 下一配方建议
工程师决定 → 实际运行关联 → 冻结结果 → 知识更新依据
```

每次建议冻结所使用的知识版本、来源哈希和适用范围。工程师采用、修改或拒绝建议的原因以及后续质量结果，是更新知识可信度的原始证据。

## 规则

- 每条知识声明必须有来源、适用范围、版本、审核状态和冲突处理。
- 硬约束只能缩小候选空间；软约束只能影响排序，不能伪造质量结果。
- 输入不匹配、范围超出、知识过期或冲突未解决时，系统降级为数据驱动建议或停止建议。
- 机理解释必须明确证据等级，不能把相关性写成确定根因。
- 建议记录保存实际使用的知识快照；之后的知识修改不会重写旧建议。

## 知识检索

文档知识按“来源接入与片段抽取 → 人工复核 → 关键词与可选语义索引 → 项目和适用范围硬过滤 → 混合排序 → 片段级引用”进入分析助手。只有状态为已复核的来源和人工复核片段可被检索；结果保留来源记录、页码或 Sheet、来源 SHA 与内容哈希，便于回看原文和识别内容变化。

语义索引是可重建的派生索引，不改变来源审核状态，也不成为正式业务证据。嵌入功能默认关闭；启用后复用受保护的模型服务配置，并要求供应商提供 OpenAI-compatible `/embeddings` 接口。服务不可用或某次查询嵌入失败时，系统自动使用 PostgreSQL 关键词检索，不能因为缺少向量而放宽权限或审核条件。

## 当前实现边界

当前路径支持来源、片段、声明、适用范围、硬约束、冲突、版本、建议使用追踪，以及面向分析助手的范围受控混合检索。知识是否有效由真实运行后的决定与质量结果逐步支撑或削弱；检索命中不等于声明成立，仓库不声称已经证明任何特定机理或现场收益。
